# Daily atmospheric CO₂ at Mauna Loa and Barrow: trend-aware preprocessing and chronological validation

Code, input data and result tables for

> Patidar, M., & Patidar, S. (2026). *Predicting Daily Atmospheric CO₂ at Mauna Loa and Barrow: Trend-Aware Preprocessing and Chronological Validation.* Submitted to *Journal of Geophysical Research: Atmospheres* (special collection: Scientific Impact of Long-term Observations of the Atmosphere – In Honor of Walter Komhyr).

The study predicts daily CO₂ at NOAA GML stations Mauna Loa (MLO) and Barrow/Utqiaġvik (BRW) from CH₄, N₂O and lagged/rolling features with five models (Decision Tree, Random Forest, XGBoost, LSTM, BiLSTM). The final pipeline, **DT-SQ-Optuna**, uses training-only quadratic detrending, a chronological 60/20/20 split, training-only min–max scaling and Optuna (TPE) hyperparameter search.

**Archived version (Zenodo DOI):** _to be added after the first release_

## Run order

Run the notebooks from inside the `notebooks/` folder (all paths are relative: `../data/...`, `../results/...`).

| # | Notebook | What it does | Paper role |
|---|---|---|---|
| 1 | `01_phase1_bayesian_baseline_MLO.ipynb` | Bayesian-optimised baseline, random 80/20 split | Phase 1 benchmark (MLO) |
| 1 | `01_phase1_bayesian_baseline_BRW.ipynb` | same, Barrow | Phase 1 benchmark (BRW) |
| 2 | `02_phase1_optuna_random_split_MLO.ipynb` | Optuna (50 trials), random split | Phase 1 Optuna (MLO) |
| 2 | `02_phase1_optuna_random_split_BRW.ipynb` | same, Barrow | Phase 1 Optuna (BRW) |
| 3 | `03_chronological_raw_MLO.ipynb` | Optuna, chronological split, **no** detrending | Chronological raw baseline |
| 4 | `04_phase2_dt_sq_optuna_MLO.ipynb` | DT-SQ-Optuna (final pipeline) | Phase 2 (MLO) |
| 4 | `04_phase2_dt_sq_optuna_BRW.ipynb` | DT-SQ-Optuna, Barrow | Phase 2 (BRW) |

Steps 1–4 are independent of each other (each reads from `data/processed/`), so they can be run in any order; the numbering follows the paper's narrative.

### Running the other site

Notebooks 02, 03 and 04 are written once for both sites. Open the settings cell near the top and change

```python
LOCATION = 'MLO'   # or 'BRW'
```

then run all cells. For example, the chronological raw-split result for Barrow is obtained by opening `03_chronological_raw_MLO.ipynb`, setting `LOCATION = 'BRW'` and running it (there is no separate Barrow file). Results are written to the matching `results/` folder with `LOCATION` in the file name; **copy or rename the CSV before switching site if you want to keep both**, because each run is saved under the same folder.

### Settings that differ between notebooks

| Setting | 02 / 03 / 04-MLO | 04-BRW |
|---|---|---|
| Optuna trials (all five models) | 50 | 50 |
| Pruner | MedianPruner (10 start-up trials, 5 warm-up steps) | same |
| Sampler seed | 42 | 42 |
| LSTM/BiLSTM epochs (searched as integer 10 to max), early-stopping patience | 10–50, patience 5 | 10–100, patience 10 |
| Tree-model cross-validation | 5-fold, shuffled, seed 42 | same |

## Data

`data/raw/` holds the daily NOAA Global Monitoring Laboratory in-situ records (CO₂, CH₄, N₂O) for MLO and BRW merged into one table (columns `year, month, day, CO2_value, CH4_value, N2O_value`). Original data: NOAA GML, https://gml.noaa.gov/ (please cite the NOAA data sets as given in the paper's reference list and on the NOAA GML data pages).

`data/processed/` holds the two files the notebooks actually read:

- `Imputed_BasePaper_MLO_CO2_CH4_N2O_1995_to_2022.csv`
- `Imputed_BasePaper_BRW.csv`

## Results

See `results/README.md`. Result CSVs for Phase 1 Optuna, the chronological raw baseline and DT-SQ-Optuna are included. The Bayesian baseline (notebook 01) prints its metrics inside the notebook.

Comparison figures and statistical-test tables in the paper were assembled from these result tables and are **not** generated by a notebook in this repository.

## Reproducibility notes

- Seeds are fixed (`OPTUNA_SEED = 42`, `LSTM_SEED = 42`). GPU/TensorFlow non-determinism can still change LSTM/BiLSTM metrics slightly between runs.
- The notebooks keep their saved outputs from the original runs (executed on Google Colab with a GPU).
- Installing: `pip install -r requirements.txt`. A GPU is recommended for the LSTM/BiLSTM searches.
